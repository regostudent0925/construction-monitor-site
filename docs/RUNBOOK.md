## 회차와 조사 범위

- daily: 평일 09:00. 기존 공식 공휴일 제외 원칙을 유지한다. 법정·대체·임시공휴일을 공식 달력/정부 공지에서 확인하지 못하면 조사 보류를 기록한다. 주말·공휴일은 다음 정상 평일 조사에 포함한다. 회차는 YYYY-MM-DD. 마지막 실제 저장된 daily 보고서의 window.to부터 이번 예정 09:00까지 조사한다. 최초 이관 회차는 과거 오전 10시 마감을 보존했으며 이후 회차부터 09시이다.
- weekly: 매주 금요일 10:00. E-1 7개 주제를 모두 검색하고 국내 연구를 우선한다. 최초는 직전 금요일 10시부터, 이후 마지막 해당 유형 window.to부터 이번 금요일 10시까지. 회차는 금요일 날짜. 주간 학술 보고서는 별도 휴일 이월을 도입하지 않는다.
- monthly: 매월 첫째 월요일 10:00. 직전 달 첫날 00:00부터 이번 달 첫날 00:00 미만에 최초 온라인 공개된 11개 학술지 논문을 조사한다. 월간 보고서 date는 실행일, cycle은 대상 월 YYYY-MM. window는 대상 월의 양 끝 시각이다. 최초 온라인 공개일을 우선하여 권호 발행일과 혼동하지 않는다. 온라인 선게재를 이미 집계했으면 권호 배정만으로 다시 집계하지 않는다. 뒤늦게 발견된 논문은 보완분으로 분리하고 대상 월·발견일을 명시한다.
- 예약이 늦게 실행되어도 당초 마감 시각을 임의로 늘리지 않는다. from 이상 to 미만을 기본으로 하며 날짜만 확인된 마감일 자료는 정확한 시각 미확인으로 남겨 경계 판단을 보수적으로 한다.
- 종류별 마지막 자료와 원고를 먼저 읽고 같은 회차·같은 원고를 재생성하지 않는다. 실패 후에는 같은 원고를 재사용한다. 과거 원고·근거는 덮어쓰지 않는다.

## 수집·분석

A~D는 언론 중심으로 종합지·경제지·config의 국내 건설 전문지 5곳, 해외 건설 전문매체를 살핀다. 모든 매체의 당일 기사 목록을 완전히 읽었다고 추정하지 않는다. 핵심 수치·법령·정책 단계는 가능하면 정부·공공기관 원문으로 대조한다. 출처별 조회 결과·접근 실패를 coverage에 남긴다. 홍보성 분양 광고는 제외한다. 주요 기사 선정과 실제 지면 헤드라인 확인은 구분한다.

2026-10-19 콘텐츠 보완: 원고를 단순히 기존 자료에서 이관하는 것으로 최신 브리핑을 대신하지 않는다. 기사 수 상한이나 매체별 할당량을 두지 않고 A~D 관련 후보를 폭넓게 조사한다. 같은 사건 전재기사를 늘려 이슈 수를 채우지 않으며, 독립 취재·새 수치·상반된 관점은 출처에 보존한다. 본문을 확인한 출처만 readLevel=body, 검색에서만 발견하면 index, 과거 자료 이관은 legacy로 기록한다. 기관 원문은 sourceKind=official로 구분한다. 출처별 기사 수는 원문 링크 중복 제거 기준이며 사실 검증 완료를 뜻하지 않는다.

전문지5곳의 접근 기록을 매번 남기고, 접근 실패 매체가 있으면 종합·경제지 최소2곳과 해외 전문매체를 추가 조사한다. 시작 주소는 config의 generalNewsSources/internationalNewsSources를 참고한다. 403·로그인·robots 제한을 우회하지 않는다. 검색 결과 제목만으로 요약을 만들지 않는다. A~D 각각 domainCoverage에 checked/no_new/partial/not_checked와 확인 범위·누락 이유를 기록한다. 분야별 새 이슈가 없을 수 있으며 빈 칸을 관련 없는 기사로 채우지 않는다. 원문 HTML의 메뉴만 추출됐으면 본문 확인으로 표시하지 않는다. 기사의 AI 요약/AI 해설과 기자 본문도 구분한다. 정규 오전09시 마감을 유지하고 이후 기사는 다음 회차로 넘긴다. 내용 보완 재발행은 원래 회차의 revision을 올리고 조사기간을 바꾸면 이유를 명시한다.

B와 D는 건설 키워드가 없는 청년고용·경력사다리·직업훈련·AI 노출도·초급업무 자동화 등 산업 횡단 변화를 별도 검색한다. 한국은행·한국노동연구원·한국고용정보원·고용노동부·통계청·국가통계포털을 원자료 조사대상에 포함한다. 건설업을 직접 분석하지 않은 자료는 산업 횡단 자료임을 밝히고 원자료의 확인 사실과 건설 분야 적용 가능성을 분리한다. 경제·IT 매체와 뉴스 포털은 발견 경로로 활용할 수 있으나 공식 원자료 또는 언론사 원문을 대표 출처로 우선한다.

홈페이지 생성 시 매체별 본문 확인 기사 수·A~D 구성·접근 제한을 사실 기록으로 산출한다. 기사 수나 단일 매체 비중으로 통과·미달을 판정하지 않는다. 기관 원문 검증과 사용자 승인은 별도이다.

E-1은 config의 7개 주제를 각각 국내 학술 검색(KCI, RISS, ScienceON 및 발행기관)에서 우선 조사하고 중요한 해외 방법론은 출판사/DOI 원문으로 확인한다. 검색 결과만으로 초록이나 전문을 읽은 것처럼 쓰지 않는다. 인력수급·임금·경력·교육·AI 직무전환·배치 생산성·정책 해외사례별 검색어와 조사 결과를 coverage에 기록한다. 확인 논문의 목적·국가/표본·방법·핵심 결과·한계·활용 가능성을 요약하되 초록에 없는 수치·표본을 만들지 않는다.

E-2는 11개 학술지 각각의 공식 목차/선게재 목록을 확인한다. 검색 상위 몇 편만으로 전체 동향이라 부르지 않는다. coverage는 K01~K05, F01~F06 모두 필수이며 checked(대상 기간 목차를 전부 확인), partial, blocked, not_checked로 남긴다. 확인한 논문마다 대표 주제 1개를 12개 범주에서 지정한다. AI 활용은 yes/no/unknown 별도 태그이며 단순 BIM 언급을 AI로 판단하지 않는다. 제목만으로 AI 미사용을 확정하지 않는다. 전체 분모는 수집 범위 내 중복 제거 논문 수, AI 활용 분자는 yes 수, 미확인 수를 함께 기록한다. 일부 학술지 접근 실패이면 전체 11개 모집단에 일반화하지 않는다. 전월 비교는 동일 coverage일 때만 하거나 비교 한계를 명시한다.

논문 중복은 DOI 우선, 없으면 공식 원문 URL로 통합한다. E-1과 E-2의 목적이 다르므로 같은 논문이 각각 등장할 수 있으며 보고서 종류가 다른 것은 삭제하지 않는다. 같은 사건의 기사는 사람이 검토한 안정된 eventKey를 동일하게 부여한다. 동일 URL·DOI·eventKey는 시스템이 통합하며 출처·대안 요약을 보존한다. 제목 유사도만으로 임의 통합하지 않는다. 전일 사건에 새 정보가 있으면 동일 eventKey로 업데이트해 이전 회차 연결을 남기고, 새 정보가 없으면 반복하지 않는다. 발행처 수는 도메인/기자 수가 아니라 발행처 명칭으로 집계하며 전재·보도자료 공통 의존 여부를 본문에 구분한다.

## 원고 형식과 저장

각 원고는 UTF-8 JSON으로 프로젝트 work/inbox에 저장한다. 템플릿은 docs/report-template.json. kind, date, cycle, generatedAt, window.from/to, title, highlights, markdown, items, coverage, limitations가 기본이다. items는 title, summary(확인 사실), interpretation(분석/한계), classification, eventDate(미확인 null), sources를 가진다. sources는 publisher,url,publishedDate(미확인 null),publishedAt(실제로 확인한 경우만),accessedAt(확인 시각; 이관 자료 미확인 null)를 보존한다. 학술 논문은 doi, journalId, evidenceLevel(fulltext/abstract/metadata), aiUse(yes/no/unknown)를 추가한다. E-1 classification은 E1-1~7, E-2는 12개 주제명이다. 공개 가능한 요약만 저장하며 기사/유료 논문 전문 복제는 하지 않는다.

프로젝트 루트에서 `node scripts/cli.mjs ingest work/inbox/원고.json`을 실행한다. 검증이 통과한 원고만 data/reports에 회차별 r1,r2 형태로 불변 저장되고 dist/catalog.json과 홈페이지가 재생성된다. 동일 내용은 duplicate:true로 반환한다. lock 충돌이면 다른 실행 종료를 확인하고 재시도한다. 불확실한 lock을 임의 삭제하지 않는다. 로컬 저장 후 배포 실패는 로컬 저장 성공·홈페이지 갱신 실패로 구분한다. 보고서 단위 SHA-256은 정규화 객체를 기준으로 하며 자료 사실 검증을 뜻하지 않는다.

## 홈페이지 자동 반영

### Codespaces·GitHub Pages 경로

GitHub 저장소를 운영 원본으로 사용하며 Codespaces는 수정·검증 환경, GitHub Pages는 정적 홈페이지 호스팅으로 사용한다. 새 브리핑을 `node scripts/cli.mjs ingest`로 보관한 뒤 전체 시험을 통과한 변경만 저장소 `main`에 반영한다. `main` 갱신은 `.github/workflows/deploy-pages.yml`을 실행하며, 이 작업이 `data/reports`에서 홈페이지를 다시 생성하고 `dist`를 Pages에 배포한다. 배포 작업 성공과 Pages URL의 새 보고서 ID를 확인한 경우에만 홈페이지 반영 완료로 기록한다. Codespaces 자체 포트는 개발 미리보기이며 상시 배포 주소로 간주하지 않는다. 세부 절차는 `docs/CODESPACES_DEPLOYMENT.md`를 따른다.

`work`, `.env`, 토큰, 쿠키, 비공개 연구자료는 GitHub에 올리지 않는다. 보고서 JSON과 홈페이지에는 공개 가능한 요약·출처 메타데이터만 포함한다. 원격 변경이 있으면 강제 덮어쓰지 않고 최신 `main`을 기준으로 충돌을 해소한다.

공개 주소는 `https://regostudent0925.github.io/construction-monitor-site/`이다. 예약 실행 때 원고를 검증·보관한 뒤 `npm test`와 빌드를 통과한 변경만 `github/main`에 반영한다. `work`, `.env`, 토큰, 쿠키, 비공개 연구자료와 관계없는 로컬 변경은 커밋하지 않는다. 원격 변경과 충돌하거나 작업 폴더가 안전하지 않으면 강제 push하지 않고 원고를 보존한 뒤 실패 원인을 보고한다.

이번 방식은 정적 아카이브를 예약 실행 때 재배포하는 초기 구현이다. 실시간 외부 쓰기 API·Cloudflare D1·기관 SSO는 설정하지 않았다. 사이트는 PC가 꺼져도 열리지만 새 수집·갱신은 로컬 Codex/PC와 연결 도구가 실행 가능해야 한다. 24시간 무인 갱신을 보장하지 않는다. 클라우드 일정은 별도 중복 생성하지 않는다. 향후 상시 운영 전환 시 기존 로컬 일정을 먼저 중지한 후 서버 수집기·인증된 writer·영구 DB·알림을 함께 검증한다.

## 실행 결과 보고

조사기간·기사/논문 수·출처 누락·원문 확인 수준·로컬 원고 ID·배포 버전/성공 여부를 한국어로 간결히 보고한다. 저장/배포/연구내용 검증/사용자 승인을 구분한다. 새로운 자료·변경·실패·필요 조치가 없으면 반복 상태 알림은 하지 않는다. 휴일 조사 보류 시 기존 조용히 종료 원칙을 따른다.
